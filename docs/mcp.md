## 实现与接口

`modules/mcp/` 提供配置、服务端地址许可、握手与发现、不可变快照、差异、原子导入和健康检查。`integrations/tools/mcp_adapter.py` 接入 10 的注册表与执行器；`creativity-web/src/features/mcp/` 通过 06 的模块登记入口提供连接、鉴权、测试、发现、差异、引用影响和调用记录入口。

管理接口为 `/admin/v1/mcp-connections` 的 GET/POST，单连接的 GET/PATCH，以及 `credentials`、`test`、`discover`、`enable`、`disable`、`imports`、`impact` 和 `discoveries/{id}/diff`。不存在面向业务客户端的直接 MCP 执行 API。管理动作由独立 `mcp:manage` 权限控制；导入另外要求目标工具的管理与版本编辑权限，发布仍要求 10 的独立发布授权。

新连接未启用；测试包含握手及工具能力验证，发现另存不可变快照。只有当前配置已通过测试和发现且凭据仍有效，才可启用。配置或凭据修改使测试失效并回到未启用状态。配置修订与记录修订分离，健康更新不会伪造配置变化；并发修改仍检查记录修订。

导入必须明确本地显示名称、用途、负责人、影响类型、必要业务权限、超时、结果上限及输出校验结构。只读执行同时要求远端声明只读及本地人工确认；远端未声明只读的工具可以按真实写入影响登记草稿，P0 不执行写操作。输入在本地封闭并使用 10 的受信字段检查，远端描述不能授予权限。

`ToolService.import_draft(..., uow=..., import_key=..., target_tool_id=...)` 是扩展的组合事务入口。调用方先完成授权与配置验证，按 `import_keys` 获取全部锁，再在同一事务中写入本地工具/草稿版本、来源关联、审计和导入映射。连接、远端名称及发现快照组成幂等键，重复提交返回首次映射；中途失败全部回滚。指定 `target_tool_id` 时必须属于同一连接和远端工具，只新增草稿版本，不修改既有版本和发布映射。

## 传输与凭据

SDK 精确锁定为 `mcp==1.30.0`，只开放远程 Streamable HTTP。stdio、OAuth 用户委托不可执行，页面明确标记。服务凭据由公共 `CredentialService` 加密保存，连接只保存引用与凭据修订，页面只返回掩码。

服务器配置前缀为 `CREATIVITY_MCP_`，`DESTINATIONS` 使用公共 `Destination` 结构：渠道、环境、用途 `mcp`、域名、端口、协议、路径范围及显式允许网段。`KEY_VERSION` 和 `ENCRYPTION_KEYS` 指定当前加密主密钥版本与 Base64 编码的 32 字节密钥。没有登记目的地或主密钥时相应功能拒绝执行，不提供默认生产凭据。公网域名也须显式登记；内网必须另外提供精确允许网段。服务 URL 不接受查询参数、用户信息或模型覆盖。

自有 httpx/httpcore 传输连接本次核准 IP，TLS/SNI 保留原主机名，禁用环境代理继承、重定向和压缩响应；SDK 本身的重定向不会绕过此传输。每页响应及发现总量受限，最多 100 页、1000 个工具及 2 MiB 定义；循环游标和重名工具拒绝保存。

每次操作创建独立 HTTP 池与 SDK 会话，操作完成或失败即关闭；不保留可被下一次操作复用的认证池、远端会话或发现缓存。活动会话标识包括渠道、环境、连接、配置修订、凭据引用与版本。凭据轮换后新请求只能选择新引用，在发送工具请求前再次检查配置与凭据。旧会话只允许完成已经提交的在途操作，结束即释放。

测试/发现连通失败最多重建一次；业务适配器从不自行重放 `tools/call`。已提交后断连使用 `MCP_RESULT_UNKNOWN` 记录结果待核实；其他可恢复失败是否重试交由 10 的策略与独立 Attempt 决定。明确鉴权失败记录健康状态并阻止重复探测，更新凭据后恢复测试。错误不会回显远端异常正文、令牌或认证头。

## 固定契约与执行

本地绑定固定导入映射及远端结构摘要。每次实际调用先读取当前连接与凭据状态，再握手并完整分页发现，核对远端工具仍具有相同输入、输出及行为声明。已观察到的契约漂移标记旧导入不可用；工具页和依赖检查显示原因，必须导入新版本并重新验证 Agent。描述差异独立显示，发现不修改任何权限或正式依赖。

`AdapterRegistry.register_resolver` 支持跨进程按持久化绑定解析；实例重启不依赖之前进程的内存注册。工具配置通过 `binding_option_providers` 显示本渠道 MCP 绑定，`binding_checks` 在执行前及依赖查询时验证当前状态。MCP 当前不启用工具结果缓存，避免旧凭据、契约或权限状态复用结果。

结构化结果优先使用 MCP `structuredContent`，只有文本时返回 `{ "content": [...] }`，必须与人工配置的输出 schema 相符。MCP 的 resource link、内嵌资源和媒体不能被当作平台文件；明确的 `artifact_id` 等引用继续由 10 的结果、体积、删除屏障及实时文件授权校验。认证信息不得被远端回显到发现记录或结果中。

连接停用仅阻断新调用与重试；已取得的在途结果仍经过身份、工具授权、schema 与文件检查并保存实际完成记录。没有取得结果的断连调用保留待核实错误。预算、调用次数和正式 Agent 白名单继续由 17 注入的 `ToolRunPort` 管理。业务调用仅获准使用本次固定工具绑定的凭据，凭据管理权限不授予调用者；凭据服务仍复核渠道、环境、状态和版本。受信渠道、环境、业务数据域、主体及调用方通过 `_meta["creativity.identity"]` 传递，模型参数不能填充该元数据，来源服务继续负责自身业务授权。
