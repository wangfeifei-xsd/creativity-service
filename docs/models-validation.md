## 协议与验收对应

协议测试走已安装 LiteLLM 的转换及 HTTP 传输接口，使用可控 HTTP 响应验证本模块行为。没有以 LiteLLM 的能力声明代替具体连接的验证证据。

| 范围 | 已验证行为 |
| --- | --- |
| Chat Completions / Anthropic Messages | 非流式文本、工具调用标识及参数、供应商请求标识、原始 usage 与归一化；Messages 流式事件和累计缓存用量 |
| MOD-A02 | 工具能力未验证或不支持时拒绝正式候选；路由依赖在保存和发布时检查当前能力 |
| MOD-A04 | Chat 流输出后中断产生失败，不能标为可重试并拼接其他正文；适配器只发一次 HTTP 请求 |
| MOD-A05 | endpoint、模型名或关键配置变化使旧证据失效；地址改回原值也不会恢复旧能力 |
| MOD-F04 / F06 / F10 | 不支持参数明确拒绝；401/403/400 不重试，429/500 分类为可恢复；schema 无效返回稳定错误，不自行进入修复循环 |
| 出站和取消 | 目标主机/IP 绑定、重定向和重复发送拒绝；取消中止待处理 HTTP；失败或取消仍保留已捕获用量，标记非最终计量 |

两个协议的计量子集样例见 [usage-examples.json](../contracts/models/usage-examples.json)。缺失为 null；Chat 缓存读取是总输入子集，Messages 原始缓存读写先并入总输入，再显式声明子集关系。

## 数据库、授权与页面

数据库测试验证：跨渠道及跨环境的配置/历史/测试记录不可访问；HTTP 正文不能覆盖渠道；地址策略拒绝未授权目标；并发别名冲突在服务事务中互斥；稳定别名不可改而供应商映射生成新版本；停用连接拒绝新调用且保留历史；IAM 使用授权撤销立即生效。

路由测试覆盖发布版本比较后切换、配置变化后拒绝发布、缺少价格端口时硬金额路由拒绝发布。删除标记传播至测试及版本，清理回调移除测试内容。完整迁移创建后的数据库经 `audit_database` 检查，与登记模型及存储规则一致。

调试端口测试确认未装配执行器时保存 `BLOCKED`，不产生 run、Attempt 或真实调用。模拟完成回调验证 fixture 不能授予真实能力，迟到结果不覆盖新配置。测试中的模拟 live 回调仅检验服务状态转换，不是供应商验证证据。

浏览器测试覆盖能力证据和币种/计费单位展示、调试不可执行反馈、连接编辑不回显凭据并保留原凭据引用和修订号，以及参数错误时保留输入并防止重复提交。

## 17/26 后续验收

- MOD-A01：至少两个真实供应商或协议组合输出相同业务 schema，保存各自模型及用量事实。
- MOD-A03：统一运行时按固定顺序创建独立 Attempt，执行重试/回退，并受同一 run 总限额约束、逐次入账。
- MOD-A06：与 08 有效价格及预算账本组合验证；未定价调试按政策执行，硬金额正式路由拒绝缺价。
- MOD-F01/F10：鉴权与最小调用、有限 schema 修复均接入统一 debug run；每次调用先预算准入及预占，完成后通过受信回调写入能力证据。

Responses、Gemini、视觉、embedding 仍未启用；Anthropic 原生结构化输出尚未启用。具体兼容矩阵和 `DebugExecutor`、`prepare_attempt`、`ModelEvent` 接入步骤见 [模型交接](models.md)。
