# 15 Skills 包与加载管理交接

对应 [执行方案 15](../../代码编写执行方案/15-Skills包与加载管理.md) 和 SKL-F01—F11。实现位于 `modules/skills/`，管理页面位于前端 `src/features/skills/`。开发规范引用 [rule.md](../../rule.md)。

## 管理与包格式

提供手工创建、ZIP/TAR/TAR.GZ 导入、资源编辑、包内文本编辑、文件树、发现与指令预览、依赖检查、加载测试、版本冻结、环境发布、引用影响和受控导出。新增版本从指定旧版本复制成独立草稿；发布不会升级既有 Agent 或运行的固定引用。停用技能后配置仍可查看，新的加载被拒绝。

导入接口以 `archive_base64` 接收完整归档；压缩体不超过 8 MiB、单文件 1 MiB、解压文件合计 16 MiB、归档成员不超过 128 个。入口必须是根目录的 `SKILL.md`，名称与描述放在 YAML 元数据区。路径按 NFC 规范检查；重复路径（含大小写碰撞）、路径穿越、文件目录冲突、加密归档、符号链接、硬链接和特殊文件均拒绝。引用限于包内文件或本文件锚点；不获取外部 URL。YAML 不允许别名、锚点、重复键或非 JSON 兼容值。

名称、描述及安全的扩展元数据保留；入口元数据不能携带渠道身份、平台资源标识、凭据或授权。Markdown、UTF-8 文本、JSON 可进入上下文；脚本和其他格式登记在清单中并显示不可加载原因。所有处理均在有界内存中完成，没有临时目录，也没有脚本启动器。

`.platform/skill.json` 是可移植的加载设置。工具使用 `tool_code + version_label` 声明，导入时重新查询目标渠道的已冻结工具版本。包内不接受来源渠道的具体版本 ID；导出移除 `allowed_agents`。缺少目标工具、停用、版本不匹配、能力证据缺失等情况保留为草稿问题，阻断冻结或发布。跨渠道复制采用受控导出后在目标工作区导入，得到独立资源、版本和对象。

## 版本、存储和清理

`skills`、`skill_files`、`skill_tests` 由 `0015_skills` 创建，复用公共 `resource_versions`、`resource_references` 和 `release_mappings`。本迁移接在 `0014_mcp` 后；最终头以共享迁移链为准。字段归档见 [技能模型](data-model/modules/skills.md)。

一个版本保存一份确定性 ZIP 产物，各文件清单引用该归档。包摘要由排序后的路径、媒体类型、长度、SHA-256 和可加载状态生成；读取时同时验证对象摘要与重新解析的清单。先验证，再上传新对象，最后在事务内原子登记版本与文件；已发布包没有原地修改接口。编辑草稿也创建新对象，保留加载测试快照仍引用的旧包。

长期配置包使用公共产物保存到删除处理完成；当前使用 100 年保留期表达配置生命周期，导出包为 24 小时。配置可在渠道内跨环境共享，内部读取从服务端已登记产物恢复其存储范围，授权始终复核原始调用身份，不使用请求正文提供存储范围。直接产物下载继续走公共实时鉴权接口。

登记失败或已替换且不被快照使用的产物转回过期待清理状态，由 `ArtifactService.cleanup_orphans` 回收；上传失败的暂存意图也由该处理器处理。`register_skill_cleanup` 登记文件清单和测试正文清理；资源、版本、文件、产物和测试都登记来源关系。方案 25 负责最终清理调度。

## 给 16/17 的入口

| 入口 | 输入与保证 |
| --- | --- |
| `SkillService.validate(context, version_id)` | 包完整性和当前本渠道依赖检查，返回具体缺项 |
| `SkillService.dependency_summary(context, version_id)` | 已冻结技能的内容、包和依赖摘要，工具版本固定不跟随最新发布 |
| `SkillService.loader.load(context, SkillLoadRequest)` | 统一运行与加载测试入口，返回实际内容、发现信息、省略项、冲突和预算结果 |
| `SkillService.tests(context, version_id)` | 按受信工作区返回加载测试快照，真实运行标识未接入时保持空值 |

`SkillLoadRequest` 是内部契约，不能直接接收业务客户端或模型正文。16/17 须先验证 Agent 及其工具集合、模型能力，再构造 `agent_id`、`authorized_tool_versions`、`model_capabilities` 和绑定顺序。管理测试接口不接收这些授权字段，也不能覆盖渠道；加载测试按当前技能依赖做本地检查，不代表 Agent 绑定或真实模型测试已通过。

加载按优先级升序，同优先级遵循 Agent 的绑定顺序。始终加载技能纳入入口指令；按需技能在未选中时仅提供名称描述，不读取对象存储，选中后纳入指令与指定资料。归档被读取以核验完整性，`loaded` 仅表示实际进入上下文的内容，未选择或不可解析文件始终进入 `omitted`。受支持文件中的 `{{ variable }}` 只做已声明且类型匹配的值替换，没有模板求值或代码执行。

预算单位明确为 **UTF-8 字节**，计入发现信息和变量替换后的正文，作为确定性保守上限。调用方再按实际模型做全上下文 Token 预算。超预算返回 `SKILL_CONTEXT_LIMIT`，明确列出未加载内容；声明的互斥规则组重复、同技能多版本绑定、越权工具、能力缺项或变量错误均显式失败。自然语言规则冲突不能靠静态解析自动证明，需要由包作者通过 `conflict_groups` 声明，或由运行编排报告。

`complete=false` 的结果不能直接作为成功上下文执行，17 应中止或明确调整策略。文本不能扩张权限；返回工具集合是技能依赖和已授权工具的交集。每次加载复核当前技能状态、工具状态和版本，并在文件读取后再检查修订、删除及恢复屏障。

真实模型 debug run、预算账本、Agent 上下文和完整轨迹由 17 接入。`skill_tests.context_snapshot` 固定本次版本定义、请求、摘要和结果，`run_id`、`release_snapshot_id` 在本单元均为空；不得把这些记录作为真实运行、评测或上线证据。

## 契约与样例

管理接口由 OpenAPI 生成；给 16/17 的 JSON Schema 在 `contracts/skills/`，使用 `python -m creativity_service.modules.skills.export` 更新。资源发布继续使用独立的 `release:publish` 权限；导出要求技能访问、`data:export` 和敏感内容权限，拒绝可识别的凭据文件或凭据正文，不包含测试输入、运行快照或授权配置。

四个可直接导入的 [格式样例](../examples/skills/README.md) 对应租赁诉求、服务比较、话术证据与经营指标。样例只约定资料结构，不包含正式业务政策、风险阈值或指标口径；正文仍由 22/23 经业务确认后加入。

验证记录见 [skills-validation.md](skills-validation.md)。
