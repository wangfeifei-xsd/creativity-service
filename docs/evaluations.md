# 24 效果评测与发布门禁交接

实现日期：2026-10-03。需求为 [EVL-F01—F11](../../需求文档/13-效果评测.md)，开发约定引用 [rule.md](../../rule.md)。验证范围和证据见 [验收记录](evaluations-validation.md)。

管理入口为“效果评测”，包含样本集、评测任务、对比报告和发布检查。后端位于 `modules/evaluations`，发布检查实现为 `modules/releases/evaluation.py`；API 与独立 Worker 均安装同一服务。Celery 既有 `runs.sweep` 先派发评测，再派发统一运行投递记录，无需另启评测专用进程。

## 样本与判定

样本集记录名称、能力类别、负责人和适用范围。每个版本固定完整样本、人工标签、工具夹具、参考资料版本及摘要、数据采集时间；修改标签生成新版本，历史样本保持不变。版本摘要包含标签理由及来源，后续对比要求这些条件一致。

手工样本及 JSONL 的每行对象遵循 [CaseInput 契约](../contracts/evaluations/CaseInput.schema.json)。CSV 的 `input/context/assertions/labels/human_label/source_refs/fixture` 列使用 JSON；字段映射方向为“来源列名 → 样本字段”。先预览，再携带原请求的 `preview_digest` 提交；只要存在错误行就拒绝整批，不跳过坏行。每次导入最多 1000 条、内容最多 200 万字符。

样本 `input` 和 `context` 合并为 Agent 输入，两者不可有同名顶层字段。`case_key` 用于同条件结果对齐，页面展示样本标题。真实运行转样本须有读取运行原文、管理评测和审阅权限，并显式指定输入字段及审阅理由；递归屏蔽常见凭据键、Bearer 文本、邮箱和手机号。自动脱敏不替代接入方对其领域敏感信息的人工审阅。

| 判定配置 | 含义 |
| --- | --- |
| `schema` | 对所选字段执行本地 JSON Schema 校验，不解析外部引用 |
| `equal` | 递归比较 JSON 类型和值，缺失不同于 null，布尔值不同于数值 |
| `numeric` | 按明确的绝对误差容限比较数值；失败属于确定性计算阻断 |
| `one_of / subset` | 值或返回集合必须属于接入方给定的固定范围 |
| `forbidden` | 所选内容不得包含配置的敏感值或越权实体；错误类别由样本指定 |
| `citation` | 输出引用必须来自当前子运行实际工具调用登记的证据 |
| `expected_error` | 样本预期受控拒绝或故障；授权类拒绝不匹配属于关键失败 |

字段路径使用点分字段及数组下标。`cross_scope/secret_leak/fabricated_entity/calculation/authorization` 均为关键类别，任意一次尝试的关键失败都会阻断该报告用于 prod，不会被重跑通过或平均分掩盖。

人工样本标签、结果复核、整份报告审阅分别保存。仅有人工作为判定标准的样本需要完成结果复核；确定性失败不能被人工通过改写。结果被拒绝或存在争议时阻断发布，并清除原报告审阅状态。页面分列展示确定性判定、语义评分和人工结论。

语义模型裁判是可选能力，本次没有启用外部裁判调用。判定内核保留独立语义记录结构并验证高分不能覆盖确定性错误，公开请求不接收客户端评分。后续如启用，需固定裁判配置、统一 run 及独立用量证据；不能填造模型评分。

## 执行与报告

`fixture` 固定工具版本、参数摘要、返回值、源版本及观测时间，只有唯一匹配的夹具才能执行。夹具只替换工具传输；仍复核当前工具授权、环境、域、Agent 绑定、结构、调用次数及证据。历史观测时间不会被改为当前时间。`live_readonly` 使用实际只读工具，报告提示外部数据可能变化，不能作为固定数据发布证据。所有评测均禁止真实写工具。

候选由 17 的冻结入口生成，子运行统一使用 `purpose=evaluation`。派发占位、幂等标识、run 与投递记录原子关联，重复扫描不会重复创建运行。暂停仅停止新派发；取消停止新派发并取消活动子运行；单例重跑保留所有早先运行及其用量。通用运行页面不能脱离评测任务重跑评测子运行。

运行次数上限包括重跑；Token 和可选金额预算按每个候选的运行硬上限保守预留。已运行条目的预留不会因暂时缺失用量而释放，可用额度不足的样本记为未执行。金额限制要求候选有同币种硬上限；每次实际调用仍受公共预算服务控制。

报告的分母始终为整套固定样本，分别列出失败、无效、未执行和取消；费用累加历次运行，未知费用、待核实用量单独展示，耗时以毫秒表示。支持同批基线或已完成的历史基线，显示总体通过率变化和逐条新增通过/失败。历史基线每次读取及发布时重新计算来源和结果，不信任报告缓存。

## 正式发布

先完成模型、提示词、技能与工具依赖调试及发布，再创建 `release_target=true` 的固定数据评测。正式报告使用一个发布候选，可附带一个同批基线；纯开发对比可包含更多候选。草稿依赖对比不能成为另一份正式依赖清单的证据。

首次发布要求完整报告、适用标签审阅通过、绝对阈值通过、无关键失败及人工报告审阅。后续发布还要求在同一数据、标签和时间条件下与当前发布映射的内容及依赖比较。普通质量阈值和最大回退比例由接入方配置；不能用零阈值豁免关键失败。

发布事务取得评测、内容图及已有 Agent 发布所需锁，重新核对候选内容和依赖摘要、参考资料、样本摘要、完成度、人工结论、有效期及当前基线。修改 Agent 或依赖后旧报告不能通过门禁；门禁只采信数据库事实。报告默认 7 天有效，可配置 1 至 30 天。

## 接口

完整输入输出见 [OpenAPI](../contracts/openapi.json) 和 [评测契约目录](../contracts/evaluations)。管理接口前缀为 `/admin/v1`。

| 路径 | 操作 |
| --- | --- |
| `evaluation-datasets`、`evaluation-datasets/{id}` | 创建、列表、详情 |
| `evaluation-datasets/{id}/versions` | 固定样本、夹具、标签及资料版本 |
| `evaluation-datasets/{id}/imports` | JSONL/CSV 预览及原子导入 |
| `evaluation-datasets/{id}/from-run` | 登记经审阅、脱敏的运行反馈 |
| `evaluation-cases/{id}` | 修改样本或标签并生成新版本 |
| `evaluations`、`evaluations/{id}` | 创建、列表、状态及可执行动作 |
| `evaluations/{id}/comparison` | 重建总体及逐样本对比报告 |
| `evaluations/{id}/control`、`review` | 暂停、继续、取消及报告审阅 |
| `evaluation-results/{id}/rerun`、`review` | 保留历史的单例重跑与结果复核 |
| `agent-versions/{id}/release-check` | 对当前草稿执行正式发布检查 |

`evaluation:read/manage/review/content` 分别控制元数据、管理、审阅和原文。原文还需独立 `data:read_sensitive` 权限；评测管理权限不会自动授予敏感原文或业务工具权限。操作返回 revision 冲突后须读取最新状态。

## 删除与后续交接

迁移 `0024_evaluations` 新增七张表，无历史业务数据回填；模型见 [评测归档](data-model/modules/evaluation.md)。来源图登记“来源 → 夹具/样本 → 样本版本 → 评测 → 结果 → 子 run”，候选及参考版本也有来源边。

已注册 `evaluation_case/evaluation_fixture/evaluation_dataset_version/evaluation_result/evaluation` 清理器。删除后原文、判定和人工理由不可读，报告注明可复现性变化；子 run 内容入口也检查样本来源，避免通过运行详情绕过删除。清理保留状态、摘要和用量事实，不恢复已删原文。

真实运行可来自不同主体、但必须属于同渠道同环境同域。样本使用管理 Scope 保存时，删除复核从原 run 读取其服务端 Scope，在同一内容图事务中检查原主体标记。**25 遍历这类来源边必须按渠道和来源标识定位，再读取派生记录的真实 Scope；不能只在原主体范围扫描。** 本模块已提供立即失效和内容清理处理器，25 负责全图批次、重试、保存期及恢复闭环。

26 复用 [装配脚本与说明](../examples/evaluations/README.md) 和 [固定报告](evaluations-evidence)。本次夹具证明通用框架，真实模型及 MCP 组合证据由 26 汇总；业务方负责其正式样本、标签与效果阈值。
