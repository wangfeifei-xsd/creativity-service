# 服务不变量与事务边界

模型版本 1.2.0。锁协议实现为 `core/locking`，工作单元为 `core/database`。下面列的是实际业务范围，不替代 [开发规范](../../../rule.md)。

每个事务开始前收集全部 `ResourceKey(channel_id, resource_type, business_key)`。编码为 JSON 数组 `["lock-v1", channel_id, resource_type, [业务键…]]`，UTF-8、键排序、无额外空白，SHA-256 前八字节解释为大端有符号 64 位整数；按整数升序去重取得 PostgreSQL 事务锁。工作单元要求 READ COMMITTED，其他隔离级别拒绝，防止等待锁前建立的旧快照导致重复检查失效。碰撞只会多等待。HTTP、Worker、补偿任务共用此实现；禁止使用 Python hash 或进程锁替代。没有记录时也先取得同一个业务键锁。动态扩锁与嵌套独立事务不受支持，调用方预先合并各服务的锁清单。

| 用量事件/修正 | 08 | 渠道、连接、源请求标识、事件版本；attempt id | 去重、有效累计值替换、修正轨迹与预占结算；缺失和未计价不得填零 |

| 评测、场景反馈与计算 | 21–24 | 渠道、任务/样本/反馈逻辑键 | 引用、固定版本、状态与权限后提交；确定性计算无外部等待 |

事务内不能等待对象存储、Redis、密钥服务、模型或外部工具。实时认证/授权在进入短事务前完成；本地业务校验器在事务内核对当前数据库事实。凭据明文只传给服务端调用回调。内容下载在取对象前后均检查授权、标记与版本；单文件限制 20 MiB，方案 17 的大文件/流式传输按块复核同样边界。

请求语义摘要 `request-v1` 不等同跨语言 JCS：JSON 键排序，数组顺序保留，Unicode 原样，拒绝 NaN/Infinity/非 JSON 对象；金额用十进制字符串。仅排除顶层 delivery；认证信息不属于 RunInput，extra 字段拒绝。业务 input 的 token、delivery 等同名字段不会被递归删除。契约变更须提升摘要算法版本，不能在旧幂等记录期间静默换算法。

04 增量：`system/iam-policy/all` 串行账号身份、凭据及权限变更；`目标渠道/iam-policy/all` 串行本渠道成员与资源授权。登录名仍使用 `system/login-name/规范化名`，成员自然键使用 `渠道/membership/user_id`，授权自然键使用 `渠道/resource-grant/受权类型、受权标识、资源类型、资源标识`。角色/范围变更还检查可能激活的已有授权，不从旧会话复制权限。

账号变更及 iam_revocations 意图同事务提交；退出摘要意图也是当前认证事实。Redis 清理、签发及切换在事务外进行，Lua 原子维护 TTL 与索引。补偿的 cutoff_at 只覆盖此前签发的 Token。控制面审计 environment 使用保留值 control，不得据此建立业务 Scope；跨环境/域的权限事件在 summary.affected_scopes 记录实际影响集合，并按该集合过滤审计查询。

05 增量：渠道配置、接入服务、Key 与 IAM 写入共用目标渠道策略锁；全局编码使用 `system/channel_code_index/规范化编码`，完整 Key 摘要使用 `system/key_identity_index/摘要`，映射使用 `渠道/data-scope-mapping/环境、类型、外部编号`。新渠道、环境、初始数据域、编码索引及首位管理员授权在同一 UoW 中提交。系统索引写入必须锁住 system 中的索引记录，并校验目标就是当前 UoW 的业务渠道。

归档在渠道策略锁及 11 登记的任务锁内复核有效 Key 与未终结任务。尚无 runs 表时任务数为 0；存在 runs 表却没有任务检查器时结果未知并阻止归档。11 的受理/终结协议必须共用这些锁，任务恢复与外部调用边界复用实时状态读取器。

治理会话可读取暂停状态，但仍检查 Redis、账号、成员、当前授权及资源范围。业务认证和 worker 不使用治理豁免。整渠道变更要求覆盖所有真实环境/数据域；新数据域的管理员由平台显式指定，普通权限由 IAM 在同一事务授予，不自动附带发布、导出或敏感原文权限。

## 08 用量预算

用量写入、策略变更、预占、计量事件去重、核算修正及提醒更新统一获取 `usage-ledger` 渠道锁；系统平台限额和计数统一获取 `usage-platform-limits`，所有组合锁由公共工作单元一次排序取得。供应商调用在发送意图事务提交后发起，结算另开事务。已发送未知调用不依靠到期释放，扫描释放未发送占用时在同一锁内重查最新到期时间。run 来源、Key 和用途固定；累计事件替换、增量事件去重，所有历史修正均可追踪。

## 11 运行受理与恢复

`modules/runs` 对每个运行及其派生记录统一取得 `run(channel_id, run_id)` 锁；首次幂等另取得稳定身份范围与请求键锁，会话执行使用 `conversation-execution(channel_id, environment, conversation_id)`。准入、快照、消息钩子、幂等和投递意图同事务登记。lease_version 单调增长，状态、步骤与 checkpoint 提交均核对有效租约。终态仅按 P0 状态图提交，资源释放由幂等补偿事务完成；外部已发送但结果不明的尝试保留费用预占和证据。

### 18 委托与连接不变量

密钥仅在 Token 已确定的渠道、环境和 client_id 下定位，验签通过后才读取源数据域。nonce 按渠道、环境、client_id、nonce 摘要取得记录互斥，与请求及完整主体声明摘要一并提交；配置/轮换同时持有 integration-config 与 IAM policy 互斥。连接名称检查、修改与脱敏测试落库共用相同配置锁；外部查询不在事务内等待。密钥吊销和数据域映射失效在 IAM 读取与出站边界复核。委托重放记录不替代运行幂等或对外业务权限验证。

## 技能包

包导入先完成有界解析、路径与引用校验，再登记草稿清单。包更新采用新对象和新文件清单，版本修订与清单切换在同一内容事务内完成；冻结版本禁止编辑。源包的资源标识与授权不能用于目标渠道绑定。加载结果仅列出实际进入上下文的文件，预算省略、不可解析、脚本禁执行和声明冲突都有对应记录；加载验证没有真实 `run_id`。

## 12 会话不变量

消息幂等与生成权共用 `conversation-execution` 锁。重放检查先于发布解析及占用；预算、轮次与消息参加 11 的同一受理事务。片段投影持有会话及 run 锁，消息完成只取有效运行终态；释放失败保留补偿证据。上下文来源及摘要版本固定，删除图锁覆盖派生写入。删除标记、状态、运行取消与共享清理意图同事务生效，跨模块清理完成前不置 DELETED。

## 13 记忆协议

`memory-subject` 使用完整 Scope 摘要加锁，在一个事务中检查容量、属性冲突、候选确认、偏好代次及清空；`memory-policy` 按渠道串行修改策略，并在使用前应用最新渠道上限。来源变更同时持有公共内容图锁。只缓存记忆版本引用，加载必须复核当前偏好代次、来源、TTL、撤销与版本；同主体同属性至多一个生效值。历史没有原文副本，权威事实写入必须匹配已登记工具结果摘要。
