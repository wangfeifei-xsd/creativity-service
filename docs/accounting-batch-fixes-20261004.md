## 查询边界

- **后台整理**：先检查会话占用、空闲时间和进行中的任务；数据库排除已消费消息、关闭记忆建议的冻结定义及遗忘水位之前的消息。最多读取 `batch_messages + 1` 条，完整轮次不拆分。运行与冻结定义按批次读取，策略只与本批实际来源及最新冻结策略取交集，已消费历史不再反复参与。提交阶段批量复核消息、运行、快照和遗忘屏障。
- **向量准备**：记忆选择、外部调用前和写回时分别批量读取记录、来源、版本和向量缓存；新向量与来源关联批量插入。保留完整 Scope、记忆版本、模型版本、偏好版本、删除屏障及向量维度校验。
- **Webhook**：用 `NOT EXISTS` 排除已有投递，按终态时间和 ID 每页读取 100 条。入队事务内复用本批重新读取的管理身份、服务配置和权限，并批量检查删除与建立来源关联。端点及待发送记录按 ID 分页，待发送查询包含到期时间和租约条件；投递列表在数据库中限制为 500 条。每次外部发送仍独立复核端点、订阅与权限，并遵守原有租约和重试次数。
- **保留期**：每种资源先在数据库中按自身期限筛选，并关联排除删除标记，每种最多返回 `limit` 条后合并为全局最早的一批。SSE 和到期用量的从属记录批量删除；独立删除清单按 200 条导入；对象扫描只查询当前对象页对应的元数据。保留待结算用量、各类 TTL、渠道归档保留期和恢复屏障。

数据库表结构未变，无需迁移。内部 `ModelEvent.request_sent` 缺省改为未知（`null`），显式 `false` 才表示确认未发送，交接契约已重新导出。
