# 多层记忆交接

对应 [执行方案](../../代码编写执行方案/13-结构化记忆管理.md) 与 [MEM 需求](../../需求文档/08-记忆管理.md)，开发规范引用 [rule.md](../../rule.md)。

| 层级 | 内容与生效方式 | 运行使用 |
| --- | --- | --- |
| 会话 | 已有会话消息、上下文与摘要，随对话正常保存 | 当前会话上下文 |
| 归档 | 后台整理完成轮次的经历摘要；保留全部来源依赖 | 跨会话回顾，明确标注为过去经历 |
| 人物画像 | 通用或渠道配置属性，模型推断先待确认；明确保存、确认后生效 | 与当前输入冲突时，当前输入优先；实时事实通过工具查询 |

记忆归档不会改变会话的 ACTIVE/ARCHIVED 状态。关闭长期记忆暂停归档、画像生成及跨会话读取，保留正常会话和已有记忆；清空删除长期内容，并阻断旧消息重新生成。

## 后台运行

升级到 `0033_layered_memory`，运行现有 Celery Worker 和 Beat。`memory.sweep` 每 60 秒按渠道分页扫描，默认会话空闲 1800 秒后按每批 20 条消息整理，切分点保持完整轮次。只使用成功完成、显式允许记忆整理的正式 Agent 对话；不在消息接收、回复或运行终态钩子抽取。

`memory_consolidations` 保存来源批次、冻结策略与属性、原调用身份的运行引用、生成运行、状态和重试进度，不保存对话原文。独立生成运行使用原 Agent 冻结模型路由，两次调用分别生成归档和画像候选；不调用业务写工具。模型调用复用统一计量、预算、租约和步骤恢复，并归入正式运行用量。自动生成失败最多 3 轮，退避重试；超限可从“记忆管理 → 后台整理”查看状态及显式重试。

创建、执行、每次模型返回和最终写回均复核当前授权、渠道/Agent 策略、主体偏好修订、有效期及删除屏障。重复扫描、投递及进程恢复复用固定批次和幂等运行。图片、音频与附件原文不被默默解释：当前整理输入只包含消息的文本部分。单批文本超过 24 KB 时明确失败，可缩小批次。

最终写回通过运行服务的成功回写事务完成：先在同一组锁内校验生成运行的取消状态、时限和租约，再原子保存归档、画像候选、整理完成状态及运行成功结果；失败整批回滚。取消先取得锁时不写记忆，已成功提交后再取消则保留成功结果。已取消的整理任务在扫描时标记为“已停止”，不会自动重启。

平台或渠道的请求量、并发及预算限额拒绝准入时，任务保留原批次、生成轮次和幂等键，等待 5 分钟再试；额度恢复后继续执行，受理成功即清除限流错误。准入等待不消耗最多 3 轮的生成失败重试次数。权限撤销、来源失效及策略关闭仍会停止任务，并发扫描的迟到错误不能覆盖已推进的任务。

## 属性与策略

`GET/PUT /admin/v1/memory-policy` 提供渠道画像 `attributes` 和后台 `consolidation` 配置；更新带 `revision`。属性包含 key、label、memory_type（PREFERENCE/FACT）及 value_schema。默认提供偏好语言、沟通偏好、长期兴趣和时间偏好；平台运行时不含游戏、玩法、预算或会员字段分支。已有渠道的旧属性通过冻结迁移转为显式配置，已有记忆不改写。

前端按定义提供文字、数字、布尔、枚举、文字数组及复杂 JSON 值编辑；服务端验证结构、允许类型、大小和敏感凭据。FACT 仍要求受控工具证据，模型候选不能伪造权威来源。`attributes` 与整理时间只在渠道配置，Agent 声明只能收紧渠道授权。Agent 发布快照也属于显式记忆声明，无须再复制一份同样的策略记录。

## 接口与装配

服务位于 `modules/memory/`，应用为 `app.state.memory`，后台实例为 `runs.memory_consolidation`。业务接口前缀 `/api/v1`，管理接口 `/admin/v1`：

| 接口 | 行为 |
| --- | --- |
| GET /memories | 可按 layer=archive/profile、属性、状态筛选；稳定分页游标绑定完整范围与筛选条件 |
| GET /memories/{id} | 详情、来源、版本与允许动作；历史不保留旧内容副本 |
| POST /memories；PATCH /memories/{id} | 明确保存与带 revision 的修正，不接受客户端来源、渠道或主体覆盖 |
| POST /memories/{id}/confirm | 确认画像候选，模型不能自行激活 |
| DELETE /memories/{id}；POST /memories/clear | 立即遗忘并提交删除任务 |
| GET/PUT /memory-preferences | 主体记忆开关；关闭和清空语义独立 |
| GET /memory-consolidations | 最近 100 个当前授权范围内的整理任务 |
| POST /memory-consolidations/{id}/retry | 带 revision 重试失败任务，沿用原来源与授权身份 |

管理入口通过已有会话或记忆的 anchor_id 恢复主体，不能扩大当前渠道、环境和数据域。后台运行也必须有 memory:read、memory:write、conversation:read、run:create 及相应数据权限。

运行只调用 select/load，选择记录与真实模型输入包含记忆版本和来源；归档与画像分开放入上下文。旧 write_candidate/write_fact 内部端口保留兼容，不接入对话埋点。属性和向量召回均先限定完整 Scope；语义检索与实际加载再次检查偏好、当前版本、来源与有效期，故障遵循 OMIT/FAIL。

## 来源删除与恢复

归档为本批全部消息的联合派生，source_mode=ALL；任一来源删除，整段归档及依赖它的画像候选立即不可用。人工确认形成独立来源后，按既有独立依据规则处理。删除传播继续清理记忆、向量、生成运行内容与恢复快照；清空和单项遗忘的时间屏障防止旧任务重新写回。新消息仍可形成新的记忆。

验收记录见 [记忆验证](memory-validation.md)。
