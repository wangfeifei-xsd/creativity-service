# 14 MCP 验证记录

验证日期：2026-10-02。实现见 [mcp.md](mcp.md)。

## 受控服务与真实基础设施

`tests/test_mcp_transport.py` 使用独立 TCP HTTP 服务与锁定 MCP SDK；`tests/integration/mcp/` 使用真实 PostgreSQL、Redis、IAM 和相同协议服务。MCP 专属共 17 项（传输与差异 7 项、集成 10 项），工具管理集成另外 4 项通过。

| 验收 | 已验证行为 |
| --- | --- |
| MCP-A01 | 发现不创建本地工具或 Agent；导入只生成草稿，没有发布映射；并发重复导入只落一份映射，事务失败连同工具草稿回滚 |
| MCP-A02 | 必填参数变更生成破坏性差异；旧快照不变，发送前拒绝旧契约，已观察漂移的绑定不可用；目标工具新增草稿版本，旧版本不改写 |
| MCP-A03 | 同名远端工具来自不同连接时映射和本地工具独立；跨渠道读取拒绝 |
| MCP-A04 | 凭据轮换使配置未启用；旧会话不复用；鉴权失败阻止密集探测，错误和日志没有完整服务令牌 |
| MCP-A05 | 断连的已提交工具请求只有一次真实发送；统一执行器记录 Attempt；连接停用后保留已取得的在途结果并拒绝下一次调用 |
| MCP-A06 | 超大 HTTP/工具结果被拒绝；远端资源 URI 和媒体不能成为平台文件，结构化未授权文件引用被工具层拒绝 |

补充验证包括：完整分页及循环游标拒绝、协议不兼容、重定向拒绝、两个渠道并发连接同一远端而不共享认证、同一渠道新凭据使用新会话、受信身份独立于模型参数传递、执行只使用固定绑定的凭据且不要求凭据管理权限、健康检查租约并发互斥、失败阈值与人工启用独立、请求体渠道覆盖与 stdio 拒绝。工具集成的实际 schema 审查覆盖新 MCP 表及完整迁移链。

## 真实远程兼容记录

连接 `https://mcp.deepwiki.com/mcp`，使用 MCP SDK 1.30.0 完成实际 TLS/HTTP、initialize、initialized 通知及 tools/list。服务名称为 DeepWiki，协商协议 `2025-11-25`，发现 3 个工具。原始服务信息、能力与完整发现定义记录在 [mcp-remote-validation.json](mcp-remote-validation.json)，没有发送业务 tools/call。

本机网络代理的 DNS 返回保留测试网段，验证只显式允许该域名当次解析的精确两个 IP，并按原域名验证 TLS；没有修改全局出站策略或生产白名单。初次未提供显式网段时出站策略按预期拒绝。

## 页面和工程检查

`tests/mcp.spec.ts` 的 3 项 Chrome 浏览器测试通过：状态与差异、要求本地权限和执行策略的导入表单、390px 窄屏及不可用连接方式。浏览器使用本机 Chrome（`PLAYWRIGHT_CHANNEL=chrome`）；接口响应为受控页面夹具，数据库与协议验证独立完成。

前端 `pnpm check` 通过类型、lint、14 项单元测试、API 类型一致性和生产构建。后端 `make check` 完整通过：128 项非集成测试、全量格式与 lint、198 个源文件的严格类型检查、全部模块契约与主 OpenAPI 校验、统一数据模型归档和存储审查均通过。当前迁移链只有 `0019_parallel_runs` 一个 head；真实数据库的结构审查通过。

实际只读远端工具调用、正式 Agent、正式运行预算和取消/恢复组合链仍归 17/26，本记录不把这些能力标为已验收。
