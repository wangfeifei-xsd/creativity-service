# 数据库初始化 SQL 归档

空库初始化分为两份纯 PostgreSQL SQL，按顺序执行：

| 文件 | 内容 |
| --- | --- |
| [init.sql](init.sql) | 全部应用表与迁移版本表的最终结构、普通索引、中文表和字段注释，不含数据写入 |
| [init_data.sql](init_data.sql) | 系统渠道、预置业务渠道及目录、开发环境首位管理员与内容授权、供应商模板、DeepSeek 模型及密文凭据、租号 MCP 基本配置与鉴权、并发限额与版本、菜单、内置角色，以及天气助手、订单协助完整配置、内容恢复屏障、技能对象字节，最后登记迁移版本 |

文件头记录配套模型版本与迁移基线。[init_data.json](init_data.json) 保存基础种子及租号 MCP 基本配置与鉴权，[weather_data.json](weather_data.json) 保存天气助手配置及必要依赖，[rental_order_guidance_data.json](rental_order_guidance_data.json) 保存订单协助助手当前完整配置。生成器逐层校验并按标识合并；订单协助归档更新共享模型、通用路由和租号 MCP 的当前配置。初始化只导入配置，不导入运行、使用、用量、测试、审计和发布操作历史，也不保留指向这些历史的来源关联或授权。正常生成与检查不重新查询数据库。

## 执行

使用 PostgreSQL 17 的 UTF-8 空数据库，连接账号需能在目标 schema 建表。通过 PostgreSQL 客户端的 `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER` 和密码配置连接目标数据库，在服务端目录执行：

```bash
psql -X --set=ON_ERROR_STOP=1 --file=sql/init.sql --file=sql/init_data.sql
```

脚本使用连接的当前 schema，通常为 `public`；如使用其他空 schema，通过 `PGOPTIONS='-c search_path=目标schema'` 指定。文件为纯 PostgreSQL SQL，也可在支持完整脚本与事务的数据库客户端执行，不需要 Python、应用配置或逐个运行历史迁移。

两份文件分别在事务中提交，并共用现有迁移锁。建表存在同名表会报错并回滚本次建表；数据导入失败会整体回滚数据和版本标记，已建结构保留，处理原因后可单独重试数据文件。交互式客户端遇错后执行 `ROLLBACK` 结束失败事务。

**必须完成两份导入后再启动服务或执行迁移。** 不能仅导入表结构后执行 `make migrate`，否则 Alembic 会尝试重新建表。归档只用于新空库，不覆盖已有库；已有数据库继续使用 `make migrate`。数据文件以迁移记录为整批完成标记，重复执行不再插入，也不会重置管理员密码；已有迁移记录的数据库同样不会导入归档数据。

导入成功后，数据库版本已登记到文件头所列修订；`make migrate` 可直接接续后续版本，无需额外 `stamp`。系统渠道已创建，`make channels-init` 再次执行也不会重复创建。

数据归档已创建启用的初始管理员，配置好应用环境与 Redis 后直接使用统一登录入口：

- 登录名：`admin`
- 初始密码：`qwerty123$%^`
- 角色：平台管理员
- 首次登录必须改密；改密前不能执行管理操作。

SQL 和 JSON 中仅保存该密码的 PBKDF2-SHA256 安全摘要，不保存明文密码。默认密码是公开的部署初始凭据，不作为正式环境长期凭据。**此次归档不修改当前环境 admin 的密码或账号关联。** 仅复制下述预置渠道、初始管理员开发环境权限、指定 DeepSeek 模型、租号 MCP 与订单协助及天气助手完整配置；不复制其他账号、生产环境权限、登录 Token 或渠道接入凭据。归档保留四个不可用于账号分配的历史兼容角色，避免破坏成员角色目录。

寻弈乐竞另预置开发环境的 `DeepSeek V4 Flash`：供应商模型名和稳定别名为 `deepseek-v4-flash`，连接地址为 `https://api.deepseek.com`，协议为 Chat Completions，超时 60 秒，默认最大输出 4096 Token。供应商目前将该兼容名称转到 `deepseek-flash`（V4.1 Flash）。归档包含连接、模型、冻结版本、依赖及来源关联；模型只保留原配置实际验证得到的能力状态、配置摘要和验证时间，不导入能力测试记录、调用详情或用量，不保留测试记录标识。实际智能体使用文本生成和工具调用能力；历史能力摘要不代表新部署网络或供应商当前健康状态。

该连接的 API Key 仅以 AES-GCM 密文归档到 `credentials`，密钥版本为 `local-model-v1`；解密主密钥不写入 SQL 或 JSON。恢复时，服务端须通过不入库的 `.env.local` 或部署秘密管理配置同版本原主密钥（`CREATIVITY_MODEL_ENCRYPTION_KEYS`），或在连接编辑页重新填写 API Key。模型配置按 `.env`、`.env.local` 顺序读取，后者覆盖前者，进程环境变量优先。出站地址由供应商连接页维护，不再配置 `CREATIVITY_MODEL_DESTINATIONS`；基础种子的 `allowed_networks` 为空；天气归档为保持已验证配置及摘要一致，保留本机代理当时使用的 `198.18.0.36/32` 和 `2001:2::59/128`。订单协助当前配置使用 `198.18.1.102/32`，覆盖上述连接的当前网络范围；天气配置所需的旧连接版本仍保留当时范围。恢复到其他网络时，在连接编辑页调整到实际出站范围并重新验证模型能力。主密钥由 API 与 Worker 共用，不能在已有密文后随意重新生成。

并发限额预置为平台 **20**、各初始化业务渠道 **5**，均为启用状态。平台限额归系统渠道，生效时间取导入事务时钟；渠道限额为归属对应渠道的 `HARD` 并发预算，附匹配内容与摘要的冻结策略版本。并发按尚未释放的受理占用实时统计，周期字段使用现有 `minute` 枚举，不表示每分钟重置；完成释放后可重新准入。不导入任何用量、准入记录、队列、租约、预占和提醒。后续新增渠道的限额仍通过管理功能配置，本归档不为已有数据库补写或重置限额。

当前环境的旧 `admin.role_id` 为空，归档补为 `platform_admin` 并保留其 `platform_roles` 关联；平台管理员的旧动作缺少 `menu:manage`，归档补齐以支持菜单维护。两种管理员的菜单关联按当前菜单与有效动作冻结为 `builtin_roles.menu_ids`，不作为业务渠道的通配授权。基础控制数据的导入时间取事务时钟；业务配置保留原时间与修订，初始账号凭据代次仍从 1 开始。

导入后可执行 `make storage-audit`。Redis 与对象存储由各自部署步骤初始化；可选 pgvector 扩展按 [向量环境说明](../deploy/vector.md) 启用。

## 初始迁移基线

项目尚未上线，原 26 个历史迁移已合并为 [0001_initial.py](../alembic/versions/0001_initial.py)。该文件冻结模型 1.8.0 的最终结构，一次创建 109 张应用表；版本表由迁移环境创建，共 110 张表、1665 个字段、244 个普通索引。基线不读取运行时模型，后续模型修改不会改变已经冻结的建库结果。

初始基线修订号保留为 `0034_admission_indexes`，与合并前最新版本相同。当前最新修订为 `0046_mcp_plain_credentials`；`0035_management` 新增菜单目录、自定义角色可见菜单清单与管理列表索引，`0036_role_catalog` 将内置角色目录纳入建库初始数据，增加账号选择角色及自定义角色授权类别，`0037_remove_business_type` 删除冗余渠道业务分类列，`0038_builtin_role_menus` 新增内置角色菜单清单。旧内置角色空值继续按有效动作生成导航，增量升级不回填菜单、不修改账号或密码。`0039_account_roles` 新增账号管理角色清单，旧账号未填写时继续解析已有单角色及授权关系。`0040_model_networks` 新增连接网络范围，已有连接回填空数组（仅公网）；旧服务器目的地中的内网或代理范围需转填到相应连接页面。

空库可使用本目录两份 SQL，或使用 `make migrate`。后者仍使用冻结历史菜单和角色种子，需另执行 `make channels-init`，再用 `uv run creativity-iam init-admin --login-name admin --display-name 管理员` 交互设置初始密码；不应再执行本目录的数据 SQL。开发库执行 `make migrate` 只执行新增修订，不重建既有表。

后续结构变更通过 `uv run alembic revision -m "变更说明"` 新增修订，并同步更新模型和初始化 SQL。不要修改初始基线来替代增量升级。`downgrade base` 会删除全部应用表，只用于明确需要重建的测试库；已有数据的开发库不执行该操作。

早于 `0034_admission_indexes` 的数据库不直接接入压缩后的历史。应先用合并前代码升级至该版本，再使用当前代码；不能仅通过 `stamp` 跳过旧字段及数据迁移。合并前源码、数据库完整备份及核验快照保存在本机 `.local/backups/alembic-baseline-20261005-012534/`，不进入版本控制。模型归档的历史修订来源和历次验收记录保留用于追溯。

## 维护与验证

表结构 SQL 由当前 SQLAlchemy 模型和 Alembic 版本表定义生成；数据 SQL 由 `init_data.json`、`weather_data.json`、`rental_order_guidance_data.json` 和配套迁移修订生成。更新初始配置时修改冻结数据源，再生成 SQL；不要修改已经冻结的历史迁移种子来替代当前环境配置。密码摘要固定保存，不在每次生成时随机更换盐值。开发规范统一见 [rule.md](../../rule.md)，模型与模块归属见 [数据模型索引](../docs/data-model/README.md)。

```bash
make sql
make sql-check
uv run pytest tests/integration/test_init_sql.py -q
```

`make sql` 同时重新生成两份 SQL；生成过程不连接数据库、不加载部署秘密，输出顺序固定。`make sql-check` 同时比较两份完整内容，已纳入 `make check` 和 `make model-check`。

集成测试在真实 PostgreSQL 的独立临时 schema 顺序执行两份归档，对照迁移结构并核验冻结初始数据。验证增量升级与回退、重复导入、建表和数据导入失败回滚、默认密码真实登录及首次改密、管理员角色和菜单关联的运行时读取，以及预置渠道列表、详情、开发环境首位管理员和编码查重；同时验证平台限额立即生效、两级并发边界、超限事务回滚和释放后恢复准入。测试结束清理自身 schema 和 Redis 前缀。

## 渠道环境模型升级

`0041_channel_environments` 统一上下文为渠道、环境和主体，删除范围目录、配置列、菜单动作及管理/业务工作区分类。升级前停止 API 与 Worker 并备份数据库；在线升级转换旧授权、版本摘要、终态运行身份、幂等摘要与恢复屏障。授权按各环境分别合并，恢复中的屏障继续封锁；渠道、账号、连接凭据及模型配置保留。旧会话不兼容新契约，用户重新登录，服务端重新换取 Token 并使用 v2 委托。

已有个人内容、OAuth 身份、主体复核绑定或删除记录的数据库，需要先核对主体冲突与独立删除账本；迁移检测到这些记录或未结束运行会整体回滚。当前未上线开发库已经通过完整备份恢复与升级核验。已有数据的升级不可通过 downgrade 伪造旧范围，回退须恢复升级前备份。空库使用本目录完整 SQL；离线增量 SQL 仅适用于空数据，已有库必须在线迁移。

## 渠道管理员默认发布权限

`0042_channel_admin_publish` 为内置渠道管理员补齐 `release:publish` 及发布菜单按钮。在线升级按页批量补齐首位管理员、平台账号分配生成的完整渠道管理员授权，保留原环境范围；手工创建、收窄过的授权及非管理员授权不扩权。角色和授权变更写入审计，升级前备份，已有成员的数据库回退须恢复备份。离线增量 SQL 仅支持无成员的初始库。

新建及重新分配的渠道管理员默认可发布已授权环境中的资源；新建环境延续完整管理员授权。自动分配的发布权限仍受当前角色控制，改为不含发布权限的角色后失效。自定义角色可勾选发布，显式资源授权继续限定环境与资源，导出、其他敏感原文和运行审批仍按独立授权规则校验。初始化 JSON 与 SQL 同步预置此默认权限，模型能力未验证时仍不能发布。

```bash
uv run creativity-lifecycle backup --channel channel_407de822881947339e26ec7d9d55a8a0
```

命令使用服务端配置的 `CREATIVITY_DELETION_LEDGER_PATH`，保留已有删除意图和封锁状态。此步骤用于新空库部署；已有内容的备份恢复仍须遵循 [恢复流程](../docs/operations.md#data-lifecycle)，不能用重建清单或直接修改屏障状态解除封锁。

执行两份 SQL 后，技能对象仍需写入已配置的 S3/MinIO。原始 ZIP 已作为带摘要的 `creativity-object` 注释封存在 `init_data.sql` 中，SQL 本身不访问对象存储。使用同一服务环境配置恢复：

```bash
uv run --locked python -m scripts.restore_init_objects
uv run --locked python -m scripts.restore_init_objects --check
```

如果导入的是其他 schema，为上述命令追加 `--schema 目标schema`。脚本首先核对目标数据库中的对象标识、渠道、路径和摘要，只创建缺失对象；已存在且一致时跳过，内容冲突时拒绝覆盖，写入后重新读取校验。该步骤不依赖开发机原对象，也不要求重新上传 Skill。

然后按 [天气示例启动说明](../examples/weather/README.md) 启动本机 MCP，配置精确出站目的地；模型解密主密钥沿用上文的部署配置。新执行会请求 Open-Meteo 获取天气。

归档校验检查配置白名单、模型能力与配置摘要、版本依赖、来源引用、技能文件摘要及完整恢复屏障。PostgreSQL 集成测试在独立空 schema 导入并逐条比对全部冻结配置，确认运行、使用、用量、测试和操作表为空，并通过真实服务解析正式订单协助 Agent。测试不调用模型或租号业务工具。
