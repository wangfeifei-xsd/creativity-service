# 数据库初始化 SQL 归档

“智能体配置助手”为随平台代码提供的只读内置能力，不写入这些可编辑的资源初始化数据，也不作为智能体列表中的资源展示；通过“智能创建”和“智能修改”使用。部署代码并准备当前渠道与环境已发布、已授权的文本生成模型路由及可用凭据后即可使用，无需额外预制助手或提示词 SQL；对话运行和用户确认保存的智能体配置按当前渠道写入。智能体只保留一份当前配置，任务指令直接保存在该配置内；保存不改变上下线和启停状态。

空库初始化分为两份纯 MySQL 8 SQL，按顺序执行：

| 文件 | 内容 |
| --- | --- |
| [init.sql](init.sql) | 全部应用表与迁移版本表的最终结构、普通索引、中文表和字段注释，索引均内联于 CREATE TABLE，不含数据写入 |
| [init_data.sql](init_data.sql) | 系统渠道、预置业务渠道及目录、开发环境首位管理员与内容授权、供应商模板、DeepSeek 与 GTP 模型及密文凭据、两条已发布路由、两个 MCP 与鉴权、并发限额与版本、菜单、内置角色、订单协助和销售推荐完整配置、Core 渠道接入凭据、内容恢复屏障、三个技能包字节，最后登记迁移版本 |

文件头记录配套模型版本与迁移基线。[init_data.json](init_data.json) 保存基础种子及租号 MCP 基本配置与鉴权，[rental_order_guidance_data.json](rental_order_guidance_data.json) 保存订单协助助手完整配置、通用模型路由发布映射、开发环境权限与恢复屏障，以及陪玩 MCP 的当前连接、鉴权和最新发现配置，[gpt_data.json](gpt_data.json) 保存独立的 GTP 连接、模型和已发布路由，[sales_recommendation_data.json](sales_recommendation_data.json) 保存销售推荐智能体、两个提示词、两个技能、目录工具及完整文件字节，以及 Core 内部接入身份、渠道 Key 摘要及系统身份索引。生成器逐层校验并按标识合并；订单协助归档更新共享模型、通用路由和租号 MCP 配置，GTP 与销售推荐只追加独立配置，不覆盖既有记录。初始化只导入配置，不导入运行、使用、用量、测试、审计和发布操作历史，也不保留指向这些历史的来源关联或授权。正常生成与检查不重新查询数据库。

## 执行

使用 MySQL 8.0，在实例中为 Creativity 创建独立空库，不能复用租号业务库。连接账号需具有该库的建表、普通索引与读写权限。密码通过客户端交互输入，不放入命令行或仓库。

```sql
CREATE DATABASE creativity CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
```

准备目标环境的数据库、OSS、模型解密主密钥与独立删除清单目录配置后，在服务尚未启动时执行：

```bash
make init-import
# 如需明确指定新空库：
uv run --locked python -m scripts.import_init_archive --schema creativity
```

两条命令任选其一。导入器使用服务环境配置中的连接信息，先检查 MySQL 版本、空库、冻结归档一致性和已有删除清单，再顺序导入结构与数据、初始化独立删除清单、恢复三个技能包。它拒绝覆盖已有库，也不清除已有删除意图或封锁状态。模型主密钥、业务 MCP 的可达地址与服务端应用授权仍由部署环境提供；初始化内容保留 `dev` 业务环境，不自动改为生产授权。

文件 URL 技能包会恢复到部署配置对应的 OSS 桶和路径，并在无运行的初始化库中同步调整技能 URL、文件索引与内容摘要。旧的订单协助技能仍按产物引用恢复。全部对象只创建缺失内容，写入后重新读取核验；已有对象冲突时拒绝覆盖。后续步骤失败不会回滚已经提交的 SQL；数据已提交时，修正配置后按文末的删除清单初始化和对象恢复命令续做。若建表中断，按下文重建本次专用新库后重试。

也可沿用手动导入方式，随后执行本文末尾的删除清单初始化和对象恢复命令：

```bash
mysql --host=127.0.0.1 --port=3306 --user=root -p --default-character-set=utf8mb4 creativity < sql/init.sql
mysql --host=127.0.0.1 --port=3306 --user=root -p --default-character-set=utf8mb4 creativity < sql/init_data.sql
```

两份文件通过包含数据库名称摘要的连接命名锁与迁移互斥。每张表的字段、中文注释和普通索引都在同一条 CREATE TABLE 中定义，不再单独执行 CREATE INDEX。技能路径索引使用前 512 个字符，完整路径仍由服务层比较。

MySQL DDL 隐式提交：建表失败会保留已经创建的表，须核对错误并重建这次初始化的专用新库后重试，不能宣称整份 DDL 可回滚。数据脚本使用单独事务，锁槽、配置与迁移标记一起提交；客户端遇错必须停止执行并 ROLLBACK，不能使用忽略错误继续执行的模式。数据导入失败可保留空表并重试数据脚本。

连接使用 `mysql+pymysql://账号:密码@主机:3306/creativity?charset=utf8mb4`；异步服务内部使用 asyncmy。配置按 `CREATIVITY_ENVIRONMENT` 选择 `.env.dev`、`.env.test` 或 `.env.prod`，默认开发环境，进程环境变量优先。时间字段为 DATETIME(6)，服务入库转 UTC、出库恢复 UTC 时区；字符串使用 utf8mb4_0900_bin，避免标识大小写或尾空格被数据库自动合并。

**必须完成两份导入后再启动服务或执行迁移。** 不能仅导入表结构后执行 `make migrate`，否则 Alembic 会尝试重新建表。归档只用于新空库，不覆盖已有库；已有数据库继续使用 `make migrate`。数据文件以迁移记录为整批完成标记，重复执行不再插入，也不会重置管理员密码；已有迁移记录的数据库同样不会导入归档数据。

导入成功后，数据库版本已登记到文件头所列修订；`make migrate` 可直接接续后续版本，无需额外 `stamp`。系统渠道已创建，`make channels-init` 再次执行也不会重复创建。

数据归档已创建启用的初始管理员，配置好应用环境与 Redis 后直接使用统一登录入口：

- 登录名：`admin`
- 初始密码：`qwerty123$%^`
- 角色：平台管理员
- 首次登录必须改密；改密前不能执行管理操作。

SQL 和 JSON 中仅保存该密码的 PBKDF2-SHA256 安全摘要，不保存明文密码。默认密码是公开的部署初始凭据，不作为正式环境长期凭据。**此次归档不修改当前环境 admin 的密码或账号关联。** 仅复制下述预置渠道、初始管理员开发环境权限、指定 DeepSeek 和 GTP 模型配置、租号和陪玩 MCP、订单协助及销售推荐完整配置；不复制其他账号、生产环境权限、登录 Token 或无关接入凭据；只保留下述 Core 开发接入所需的当前摘要与密文。归档保留四个不可用于账号分配的历史兼容角色，避免破坏成员角色目录。

预置业务渠道为“寻弈乐竞”，负责人“小苏打”，编码 `XYLJ`，状态“启用”；渠道主档归自身，目录归系统渠道。首位管理员复用初始 admin，登记 channel_admin 成员及开发环境授权；首次改密后可进入订单协助所在的开发环境。同时预置“陪玩 Core · AI 匹配”专用接入服务及当前有效 Key 摘要。

供应商字典预置 DeepSeek、千问、豆包、OpenAI（ChatGPT），记录均归系统渠道，仅包含供应商名称、编码、`chat_completions` 协议及无凭据连接模板，模板超时为 600 秒。千问和豆包使用北京地域模板；千问保留仍可用的公共域名，创建渠道连接时可改为对应业务空间专属域名或其他地域地址。具体模型、密钥与能力验证仍需按渠道配置，预置模板不代表已验证模型能力，也不启用尚未实现的 Responses 协议。

寻弈乐竞另预置开发环境的 `DeepSeek V4 Flash`：供应商模型名和稳定别名为 `deepseek-v4-flash`，连接地址为 `https://api.deepseek.com`，协议为 Chat Completions，超时 600 秒，默认最大输出 16384 Token。供应商目前将该兼容名称转到 `deepseek-flash`（V4.1 Flash）。归档包含连接、模型、冻结版本、依赖及来源关联；文本生成与工具调用能力随本次额度调整重新实测，保留匹配配置的能力摘要和验证时间；其他能力保留原验证摘要，不将旧证据改写为新配置已验证。不导入能力测试记录、调用详情或用量，不保留测试记录标识。历史能力摘要不代表新部署网络或供应商当前健康状态。

`max_tokens` 是一次模型调用的输出上限，推理模型可能将推理 Token 计入其中；实际消耗还包括系统指令、资源目录、历史对话等输入，以及重试或多轮调用。上限不等于固定收费，但平台按输入估算加最大输出预占预算。订单协助的运行总额度为 256000 Token，内置配置助手为 160000。复杂任务可按需把路由输出上限提高到 32768，并同时核对运行总预算、供应商支持范围和超时；不将所有调用默认放大几十倍。本次修改用于新空库初始化，已有库通过配置管理调整，重跑初始化 SQL 不会覆盖已有模型。

DeepSeek 和 GTP 连接的 API Key 仅以 AES-GCM 密文归档到 `credentials`，密钥版本为 `local-model-v1`；解密主密钥不写入 SQL 或 JSON。恢复时，服务端须通过不入库的环境配置或部署秘密管理配置同版本原主密钥（`CREATIVITY_MODEL_ENCRYPTION_KEYS`），或在连接编辑页重新填写 API Key。模型配置按当前环境读取对应的 `.env.dev`、`.env.test` 或 `.env.prod`，进程环境变量优先。模型连接按页面配置的地址访问，测试与调用共用连接入口，不维护或校验 IP 范围。归档已移除连接及模型快照中的网络范围字段，并同步更新配置与依赖摘要。主密钥由 API 与 Worker 共用，不能在已有密文后随意重新生成。

GTP 配置于 2026年10月19日从“寻弈乐竞”开发库只读更新。连接名 `ChatGTP`，使用 OpenAI 供应商字典和 Chat Completions 协议，地址为 `https://api.masterhuang.top`，超时 600 秒。模型显示名 `GPT-6.1 Sol`，供应商模型名 `gpt-6.1-sol`，平台编码 `gtp`；上下文上限未填写，模型默认参数为空，允许设置 `max_tokens`。`GTP6.1路由`（编码 `gpt-6.1-sol`）在开发环境已发布，首选该模型、无回退模型，只要求文本生成；路由输出上限为 `max_tokens=4096`，配置及路由内模型快照同步保留。总尝试上限 3、每个模型重试 0，当前实际候选顺序仅一次调用，不启用硬金额预算。

本次核对发现开发库的 DeepSeek 当前参数已变更，能力摘要为空，而通用路由仍引用旧模型快照。为保持订单协助依赖完整，初始化继续保留原归档中已验证的 DeepSeek 配置及配套路由（默认最大输出 16384 Token），不将尚未重新验证的当前模型覆盖到可用组合中。本次只读采集未修改开发库配置。

归档保留 GTP 文本生成已支持，以及工具调用、流式输出、JSON 对象输出、原生结构化输出、向量生成未通过的实际能力结论和验证时间；未验证的能力不补造。能力摘要中的测试标识已剔除，连接健康状态与检查时间仅表示采集时结果。保存当前连接版本、当前模型版本、模型仍引用的旧连接版本、当前路由配置及发布映射、依赖和来源关联，不导入无关旧版本、价格或运行记录。新部署仍须核对主密钥并重新检查网络、鉴权与所需能力，历史验证不代表新环境当前可用。

并发限额预置为平台 **20**、各初始化业务渠道 **5**，均为启用状态。平台限额归系统渠道，生效时间取导入语句的 UTC 时钟；渠道限额为归属对应渠道的 `HARD` 并发预算，附匹配内容与摘要的冻结策略版本。并发按尚未释放的受理占用实时统计，周期字段使用现有 `minute` 枚举，不表示每分钟重置；完成释放后可重新准入。不导入任何用量、准入记录、队列、租约、预占和提醒。后续新增渠道的限额仍通过管理功能配置，本归档不为已有数据库补写或重置限额。

当前环境的旧 `admin.role_id` 为空，归档补为 `platform_admin` 并保留其 `platform_roles` 关联；平台管理员的旧动作缺少 `menu:manage`，归档补齐以支持菜单维护。两种管理员的菜单关联按当前菜单与有效动作冻结为 `builtin_roles.menu_ids`，不作为业务渠道的通配授权。基础控制数据的导入时间取 UTC 时钟；业务配置保留原时间与修订，初始账号凭据代次仍从 1 开始。

导入后可执行 `make storage-audit`。Redis 与对象存储由各自部署步骤初始化；Qdrant 按 [向量环境说明](../deploy/vector.md) 启用。

## MySQL 迁移基线

当前最新修订为 `0053_agent_configuration`，模型版本为 2.1.0。110 张应用表和迁移版本表均包含 `is_deleted`，初始化数据显式写入 `false`。`0049_soft_delete` 迁移回填原 `DELETED`、`DELETING` 状态以及具有删除标记的记忆；成员移除、资源授权删除通过最后一次写入后的成功审计识别，避免误删后来重新授权的数据。停用、归档和普通撤销保持未删除。迁移支持 DDL 中断后继续补齐，存在逻辑删除记录时拒绝移除该字段的回退，防止重新暴露数据。`0051_schedule_failures` 补齐计划失败处理字段，`0052_file_urls` 支持技能文件 URL；`0053_agent_configuration` 将智能体归并为单份当前配置，新增独立的环境上线状态，保留历史运行证据。该迁移需要连接数据库读取旧配置，禁止用 Alembic 离线 SQL 跳过数据转换；空库仍可直接执行完整初始化归档。无智能体数据时允许回退结构，已有智能体数据时须使用迁移前备份恢复。归档与当前最终结构一致。

迁移 `0050_qdrant` 将同步任务表说明调整为后端无关的中文注释；向量缓存及任务结构保持不变。当前迁移链从 [0048_mysql_milvus.py](../alembic/mysql_versions/0048_mysql_milvus.py) 开始，结构冻结在同目录的 `0048_schema.json`，菜单和角色种子冻结在 `0048_seed.json`。基线不读取运行时模型；Alembic 仅扫描 `mysql_versions`。原 `alembic/versions` 保留 PostgreSQL 历史来源，不对 MySQL 执行，也不能将旧库直接 stamp 为新基线。

空库可使用本目录两份 SQL，或者 `make migrate` 后初始化系统渠道与管理员。两种方式互斥：迁移路径只写系统锁槽、菜单和角色，需要再执行 `make channels-init` 与 `uv run creativity-iam init-admin --login-name admin --display-name 管理员`；不会自动导入业务配置归档。后续变更新增 MySQL 迁移并同步更新初始化归档，不修改本次冻结基线。

锁槽固定为 12,288 个系统渠道记录，服务根据包含渠道的资源键映射槽位，通过 InnoDB 共享/排他行锁保护事务。数据库连接使用 READ COMMITTED；哈希碰撞只增加等待，提交、回滚及断连自动释放，不依赖唯一约束。

本次本地切换采用新建库与配置归档导入；旧 PostgreSQL 数据卷保留。SQL 不包含旧运行历史，也不是跨引擎在线数据转换工具。
