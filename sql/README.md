# 数据库初始化 SQL 归档

“智能体配置助手”为随平台代码提供的只读内置能力，不写入这些可编辑的资源初始化数据。升级后即可使用；对话运行和生成的智能体草稿按当前渠道写入既有运行及版本表。智能体的任务指令保存在版本配置 JSON 内，本次功能不增加表、字段或迁移。

空库初始化分为两份纯 MySQL 8 SQL，按顺序执行：

| 文件 | 内容 |
| --- | --- |
| [init.sql](init.sql) | 全部应用表与迁移版本表的最终结构、普通索引、中文表和字段注释，索引均内联于 CREATE TABLE，不含数据写入 |
| [init_data.sql](init_data.sql) | 系统渠道、预置业务渠道及目录、开发环境首位管理员与内容授权、供应商模板、DeepSeek 模型及密文凭据、租号 MCP 基本配置与鉴权、并发限额与版本、菜单、内置角色，以及天气助手、订单协助完整配置、内容恢复屏障、技能对象字节，最后登记迁移版本 |

文件头记录配套模型版本与迁移基线。[init_data.json](init_data.json) 保存基础种子及租号 MCP 基本配置与鉴权，[weather_data.json](weather_data.json) 保存天气助手配置及必要依赖，[rental_order_guidance_data.json](rental_order_guidance_data.json) 保存订单协助助手当前完整配置。生成器逐层校验并按标识合并；订单协助归档更新共享模型、通用路由和租号 MCP 的当前配置。初始化只导入配置，不导入运行、使用、用量、测试、审计和发布操作历史，也不保留指向这些历史的来源关联或授权。正常生成与检查不重新查询数据库。

## 执行

使用 MySQL 8.0，在实例中为 Creativity 创建独立空库，不能复用租号业务库。连接账号需具有该库的建表、普通索引与读写权限。密码通过客户端交互输入，不放入命令行或仓库。

```sql
CREATE DATABASE creativity CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
```

```bash
mysql --host=127.0.0.1 --port=3306 --user=root -p --default-character-set=utf8mb4 creativity < sql/init.sql
mysql --host=127.0.0.1 --port=3306 --user=root -p --default-character-set=utf8mb4 creativity < sql/init_data.sql
```

两份文件通过包含数据库名称摘要的连接命名锁与迁移互斥。每张表的字段、中文注释和普通索引都在同一条 CREATE TABLE 中定义，不再单独执行 CREATE INDEX。技能路径索引使用前 512 个字符，完整路径仍由服务层比较。

MySQL DDL 隐式提交：建表失败会保留已经创建的表，须核对错误并重建这次初始化的专用新库后重试，不能宣称整份 DDL 可回滚。数据脚本使用单独事务，锁槽、配置与迁移标记一起提交；客户端遇错必须停止执行并 ROLLBACK，不能使用忽略错误继续执行的模式。数据导入失败可保留空表并重试数据脚本。

连接使用 `mysql+pymysql://账号:密码@主机:3306/creativity?charset=utf8mb4`；异步服务内部使用 asyncmy。配置依次读取 `.env`、不入库的 `.env.local` 和进程环境，后者覆盖前者。时间字段为 DATETIME(6)，服务入库转 UTC、出库恢复 UTC 时区；字符串使用 utf8mb4_0900_bin，避免标识大小写或尾空格被数据库自动合并。

**必须完成两份导入后再启动服务或执行迁移。** 不能仅导入表结构后执行 `make migrate`，否则 Alembic 会尝试重新建表。归档只用于新空库，不覆盖已有库；已有数据库继续使用 `make migrate`。数据文件以迁移记录为整批完成标记，重复执行不再插入，也不会重置管理员密码；已有迁移记录的数据库同样不会导入归档数据。

导入成功后，数据库版本已登记到文件头所列修订；`make migrate` 可直接接续后续版本，无需额外 `stamp`。系统渠道已创建，`make channels-init` 再次执行也不会重复创建。

数据归档已创建启用的初始管理员，配置好应用环境与 Redis 后直接使用统一登录入口：

- 登录名：`admin`
- 初始密码：`qwerty123$%^`
- 角色：平台管理员
- 首次登录必须改密；改密前不能执行管理操作。

SQL 和 JSON 中仅保存该密码的 PBKDF2-SHA256 安全摘要，不保存明文密码。默认密码是公开的部署初始凭据，不作为正式环境长期凭据。**此次归档不修改当前环境 admin 的密码或账号关联。** 仅复制下述预置渠道、初始管理员开发环境权限、指定 DeepSeek 模型、租号 MCP 与订单协助及天气助手完整配置；不复制其他账号、生产环境权限、登录 Token 或渠道接入凭据。归档保留四个不可用于账号分配的历史兼容角色，避免破坏成员角色目录。

预置业务渠道为“寻弈乐竞”，负责人“小苏打”，编码 `XYLJ`，状态“启用”；渠道主档归自身，目录归系统渠道。首位管理员复用初始 admin，登记 channel_admin 成员及开发环境授权；首次改密后可进入天气示例与订单协助所在的开发环境。接入服务和 Key 不预设。

供应商字典预置 DeepSeek、千问、豆包、OpenAI（ChatGPT），记录均归系统渠道，仅包含供应商名称、编码、`chat_completions` 协议及无凭据连接模板，模板超时为 60 秒。千问和豆包使用北京地域模板；千问保留仍可用的公共域名，创建渠道连接时可改为对应业务空间专属域名或其他地域地址。具体模型、密钥与能力验证仍需按渠道配置，预置模板不代表已验证模型能力，也不启用尚未实现的 Responses 协议。

寻弈乐竞另预置开发环境的 `DeepSeek V4 Flash`：供应商模型名和稳定别名为 `deepseek-v4-flash`，连接地址为 `https://api.deepseek.com`，协议为 Chat Completions，超时 60 秒，默认最大输出 4096 Token。供应商目前将该兼容名称转到 `deepseek-flash`（V4.1 Flash）。归档包含连接、模型、冻结版本、依赖及来源关联；模型只保留原配置实际验证得到的能力状态、配置摘要和验证时间，不导入能力测试记录、调用详情或用量，不保留测试记录标识。实际智能体使用文本生成和工具调用能力；历史能力摘要不代表新部署网络或供应商当前健康状态。

该连接的 API Key 仅以 AES-GCM 密文归档到 `credentials`，密钥版本为 `local-model-v1`；解密主密钥不写入 SQL 或 JSON。恢复时，服务端须通过不入库的 `.env.local` 或部署秘密管理配置同版本原主密钥（`CREATIVITY_MODEL_ENCRYPTION_KEYS`），或在连接编辑页重新填写 API Key。模型配置按 `.env`、`.env.local` 顺序读取，后者覆盖前者，进程环境变量优先。模型连接按页面配置的地址访问，测试与调用共用连接入口，不维护或校验 IP 范围。归档已移除连接及模型快照中的网络范围字段，并同步更新配置与依赖摘要。主密钥由 API 与 Worker 共用，不能在已有密文后随意重新生成。

并发限额预置为平台 **20**、各初始化业务渠道 **5**，均为启用状态。平台限额归系统渠道，生效时间取导入语句的 UTC 时钟；渠道限额为归属对应渠道的 `HARD` 并发预算，附匹配内容与摘要的冻结策略版本。并发按尚未释放的受理占用实时统计，周期字段使用现有 `minute` 枚举，不表示每分钟重置；完成释放后可重新准入。不导入任何用量、准入记录、队列、租约、预占和提醒。后续新增渠道的限额仍通过管理功能配置，本归档不为已有数据库补写或重置限额。

当前环境的旧 `admin.role_id` 为空，归档补为 `platform_admin` 并保留其 `platform_roles` 关联；平台管理员的旧动作缺少 `menu:manage`，归档补齐以支持菜单维护。两种管理员的菜单关联按当前菜单与有效动作冻结为 `builtin_roles.menu_ids`，不作为业务渠道的通配授权。基础控制数据的导入时间取 UTC 时钟；业务配置保留原时间与修订，初始账号凭据代次仍从 1 开始。

导入后可执行 `make storage-audit`。Redis 与对象存储由各自部署步骤初始化；Milvus 按 [向量环境说明](../deploy/vector.md) 启用。

## MySQL 迁移基线

当前最新修订为 `0049_soft_delete`，模型版本为 2.1.0。110 张应用表和迁移版本表均包含 `is_deleted`，初始化数据显式写入 `false`。已有库执行迁移时回填原 `DELETED`、`DELETING` 状态以及具有删除标记的记忆；成员移除、资源授权删除通过最后一次写入后的成功审计识别，避免误删后来重新授权的数据。停用、归档和普通撤销保持未删除。迁移支持 DDL 中断后继续补齐，存在逻辑删除记录时拒绝移除该字段的回退，防止重新暴露数据。

当前迁移链从 [0048_mysql_milvus.py](../alembic/mysql_versions/0048_mysql_milvus.py) 开始，结构冻结在同目录的 `0048_schema.json`，菜单和角色种子冻结在 `0048_seed.json`。基线不读取运行时模型；Alembic 仅扫描 `mysql_versions`。原 `alembic/versions` 保留 PostgreSQL 历史来源，不对 MySQL 执行，也不能将旧库直接 stamp 为新基线。

空库可使用本目录两份 SQL，或者 `make migrate` 后初始化系统渠道与管理员。两种方式互斥：迁移路径只写系统锁槽、菜单和角色，需要再执行 `make channels-init` 与 `uv run creativity-iam init-admin --login-name admin --display-name 管理员`；不会自动导入业务配置归档。后续变更新增 MySQL 迁移并同步更新初始化归档，不修改本次冻结基线。

锁槽固定为 12,288 个系统渠道记录，服务根据包含渠道的资源键映射槽位，通过 InnoDB 共享/排他行锁保护事务。数据库连接使用 READ COMMITTED；哈希碰撞只增加等待，提交、回滚及断连自动释放，不依赖唯一约束。

本次本地切换采用新建库与配置归档导入；旧 PostgreSQL 数据卷保留。SQL 不包含旧运行历史，也不是跨引擎在线数据转换工具。

## 维护与验证

表结构 SQL 由当前 SQLAlchemy 模型和 Alembic 版本表定义生成；数据 SQL 由 `init_data.json`、`weather_data.json`、`rental_order_guidance_data.json` 和配套迁移修订生成。更新初始配置时修改冻结数据源，再生成 SQL；不要修改已经冻结的历史迁移种子来替代当前环境配置。密码摘要固定保存，不在每次生成时随机更换盐值。开发规范统一见 [rule.md](../../rule.md)，模型与模块归属见 [数据模型索引](../docs/data-model/README.md)。

```bash
make sql
make sql-check
uv run pytest tests/integration/test_init_sql.py -q
```

`make sql` 同时重新生成两份 SQL；生成过程不连接数据库、不加载部署秘密，输出顺序固定。`make sql-check` 同时比较两份完整内容，已纳入 `make check` 和 `make model-check`。

集成测试在真实 MySQL 8 的独立临时数据库执行两份归档，逐条比对冻结业务配置，审查字段、注释和内联索引，验证数据失败回滚、重复与并行导入、空库迁移及重复升级。向量测试直接调用本地 Milvus，覆盖范围隔离、版本和维度变更、遗忘屏障及同步重试。测试不使用 H2 或 SQLite 替代目标数据库。

## 天气助手配置归档

天气归档包含“每日天气助手”发布版本和可编辑草稿、天气 Skill 与真实 ZIP 文件、工具、MCP 连接及工具绑定所需的发现/导入配置、提示词及可复用的“通用模型路由”、提示词样例、资源依赖与来源关系。保留已验证的模型能力摘要；“不支持结构化输出”仍为原验证结论，不伪造为支持。

运行输入输出、步骤、调用尝试、事件、工具证据、模型原始响应、用量账本、验证记录、MCP 检查记录、发布操作记录和审计均不归档。运行临时版本、候选版本以及指向历史的来源关联和逐条运行授权一并剔除。配置表使用明确白名单，混入历史表会使生成检查失败。

初始管理员只有开发环境权限，保留该渠道环境的会话、记忆原文读取授权，不包含导出，不改变其他渠道管理员的默认权限。恢复后的登录仍要求首次改密。启用的巡检计划在服务启动后会产生新的使用记录，用户登录或修改配置会产生新的操作记录；这些属于恢复后的真实行为。

归档显式包含内容范围的已核验恢复屏障，避免 SQL 导入绕过环境创建服务后导致模型、路由和技能列表被阻断。首次向空库导入后，还须在 API 和 Worker 开放访问前初始化独立删除清单；纯 SQL 无法写入独立持久卷：

```bash
uv run creativity-lifecycle backup --channel channel_407de822881947339e26ec7d9d55a8a0
```

命令使用服务端配置的 `CREATIVITY_DELETION_LEDGER_PATH`，保留已有删除意图和封锁状态。此步骤用于新空库部署；已有内容的备份恢复仍须遵循 [恢复流程](../docs/operations.md#data-lifecycle)，不能用重建清单或直接修改屏障状态解除封锁。

执行两份 SQL 后，技能对象仍需写入已配置的 S3/MinIO。原始 ZIP 已作为带摘要的 `creativity-object` 注释封存在 `init_data.sql` 中，SQL 本身不访问对象存储。使用同一服务环境配置恢复：

```bash
uv run --locked python -m scripts.restore_init_objects
uv run --locked python -m scripts.restore_init_objects --check
```

如果导入的是其他数据库，为上述命令追加 `--schema 目标数据库`。脚本首先核对目标数据库中的对象标识、渠道、路径和摘要，只创建缺失对象；已存在且一致时跳过，内容冲突时拒绝覆盖，写入后重新读取校验。该步骤不依赖开发机原对象，也不要求重新上传 Skill。

然后按 [天气示例启动说明](../examples/weather/README.md) 启动本机 MCP，配置精确出站目的地；模型解密主密钥沿用上文的部署配置。新执行会请求 Open-Meteo 获取天气。

归档校验检查配置白名单、模型能力与配置摘要、版本依赖、来源引用、技能文件摘要及完整恢复屏障。MySQL 集成测试在独立空数据库 导入并逐条比对全部冻结配置，确认运行、使用、用量、测试和操作表为空，并通过真实服务解析正式订单协助 Agent。测试不调用模型或租号业务工具。
